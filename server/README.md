# سرور سیگنالینگ کلاس آنلاین — مدرسه شاهد معراج

لایه‌ی سیگنالینگ واقعی (WebSocket) برای کلاس‌های آنلاین. صدا و تصویر WebRTC به‌صورت P2P بین
کاربران جابه‌جا می‌شود؛ این سرور فقط احراز هویت، اتاق‌ها، حضور و غیاب و رله‌ی SDP/ICE را انجام می‌دهد.

## اجرا (توسعه)

```bash
cd server
npm install
npm run seed        # ساخت حساب‌های نمایشی (amir / ahmadi / admin)
npm start           # ws://localhost:8081/signal
```

سپس در ریشه‌ی پروژه‌ی فرانت‌اند فایل `.env` را بسازید (نمونه: `.env.example`):

```
VITE_SIGNAL_URL=http://localhost:8081
```

برای تست از **دستگاه دیگر** در همان شبکه، به‌جای localhost آی‌پی LAN بدهید
(مثلاً `http://192.168.1.6:8081`) و فایروال ویندوز را برای پورت باز کنید.

## تست جریان واقعی

```bash
npm run test:flow   # دو کلاینت مستقل + ایزوله‌سازی اتاق‌ها (۱۴ بررسی)
```

## محیط (server/.env)

| متغیر | توضیح |
|---|---|
| `SIGNAL_SECRET` | **الزامی در پروداکشن** — کلید امضای بلیت‌ها (`openssl rand -hex 32`) |
| `PORT` | پیش‌فرض ۸۰۸۱ |
| `ALLOWED_ORIGIN` | مبدأ مجاز CORS برای لاگین (آدرس فرانت) |
| `TURN_URL` / `TURN_SECRET` / `TURN_TTL_SEC` | اختیاری — coturn با احراز هویت REST |

## احراز هویت

1. فرانت‌اند `POST /api/auth/login` را با نام‌کاربری/رمز صدا می‌زند؛ سرور با PBKDF2
   از `users.json` تأیید می‌کند و یک **بلیت امضاشده (HS256)** با `{userId, name, role}` صادر می‌کند.
2. اتصال WebSocket فقط با `?ticket=...` برقرار می‌شود؛ سرور امضا و انقضا را می‌سنجد.
3. **نقش هرگز از کلاینت پذیرفته نمی‌شود** — فقط از بلیت تأییدشده خوانده می‌شود.

افزودن کاربر جدید: `node seed.mjs <user> <pass> <student|teacher|admin> "<نام>"`

## TURN — کی لازم است؟

- **STUN** (پیش‌فرض) برای اکثر شبکه‌های خانگی/اداری کافی است.
- اگر دانش‌آموزان پشت NAT سخت‌گیر (سیمتریک/فایروال سخت) باشند، **TURN الزامی** است:
  سرور coturn نصب کنید و `TURN_URL` + `TURN_SECRET` را تنظیم کنید. سرور سیگنالینگ برای هر
  کلاینت اعتبارنامه‌ی موقت (HMAC) می‌سازد و **رمز TURN هرگز به کلاینت ثابت فرستاده نمی‌شود**.

## دیپلوی پروداکشن (چک‌لیست)

1. `SIGNAL_SECRET` و `ALLOWED_ORIGIN` قطعی تنظیم شوند (systemd/pm2 + `.env`).
2. پشت Nginx/Caddy با **WSS (TLS)** — proxy با `Upgrade` headers برای `/signal`.
3. `server` و فرانت (بیلد Vite با `VITE_SIGNAL_URL=https://signal.example.school`) مستقر شوند.
4. در پروداکشن اتصال اپلیکیشن/دیتابیس اصلی مدرسه به این سرور: احراز هویت را به بانک
   اطلاعاتی واقعی وصل کنید (جای `users.json`) و صدور بلیت را در بک‌اند اصلی انجام دهید.
5. برای مقیاس چند-سروری: لایه‌ی rooms را به Redis pub/sub منتقل کنید (اینترفیس `rooms`
   در `index.mjs` جداست).
6. ثبت لاگ و مانیتورینگ (`/healthz` موجود است).

> حالت `BroadcastChannel` فقط برای توسعه‌ی محلی (یک مرورگر) است و در بیلد پروداکشن
> هرگز بی‌صدا فعال نمی‌شود — بدون `VITE_SIGNAL_URL`، اتصال با خطا متوقف می‌شود.
